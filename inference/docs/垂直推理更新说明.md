# 垂直（DV/NV）推理 .so 更新说明（2026-11-07）

垂直和倾斜用同一份推理源码，分别编译两个 .so；区别只在 `naviParams.txt` 和检索头权重。本包的 `naviParams.example.txt` 是垂直配置。垂直训练和检索头不变，继续使用现有的 `scc_retrieval_head.pth`。

## 一、相对服务器 e 版的推理改动

| 内容 | 对垂直的影响 | 文件 |
|---|---|---|
| **PnP 一致性检验 + 检索位置回退**（本次新增） | PnP 结果须落在它所匹配的检索块内（0.75 × 块边长），且高度与先验相差 ≤ 300 m；所有候选都不一致时，输出前几名检索块（得分加权）换算的位置，置信度 0，不用于跟踪 | `consistency.py`、`backends.py` |
| **成功标志可配置**（本次新增）`report_success` | 只有列出的输出来源返回 1（定位成功），其余返回 0。失败帧只影响成功率、不计入准确率，所以把大概率错误的输出报为失败可以提高准确率 | `backends.py`、`worker.py` |
| **selfEval 打分标准**（本次新增）| 见第四节 | `self_eval.py`、`backends.py`、`tools/calibrate_self_eval.py` |
| **取消单帧超时**（本次新增） | 原适配层每帧最多等 120 秒，超时后该模态进程被杀且不重启，后续帧全部返回 0。现在默认不限时；调试时可用环境变量 `NAV_STEP_TIMEOUT_MS=毫秒数` 重新设置 | `single-so/src/adapter.cpp` |
| 偏移模型跟踪 `offset_model` | 先验误差为固定或缓慢变化时：跟踪中心 = 当前先验 + 最近一次定位的偏移量 | `prior_tracker.py` |
| 定位失败打印堆栈；`[RETRIEVAL_TOP]` 打印检索前 5 名经纬度 | 只增加日志 | `backends.py` |
| 倾斜专用功能（`oblique`、`query_crop_scale`） | 垂直配置不写这两项，行为与原来完全相同 | `oblique.py` 等 |

## 二、一致性检验与回退的效果（模拟）

S 形航线、先验为缓慢漂移的 3–4 km 偏移、AGL 1000 m、检索正确率 70%，统计误差 ≤ 150 m 的帧比例：

| 检索正确时 PnP 也正确的比例 | 原方案 | 只做检验 | 检验 + 检索回退 |
|---|---|---|---|
| 0.8 | 0.60 | 0.71 | 0.71 |
| 0.6 | 0.40 | 0.53 | 0.54 |
| 0.4 | 0.21 | 0.31 | 0.31 |

开着跟踪时，主要收益来自检验：错误的 PnP 结果不再被输出，也不会把跟踪带偏，失败帧改为输出预测位置。检索回退主要在捕获前或关闭跟踪时起作用：每帧真值都在窗口内且关闭跟踪时，得分从 0.43 提高到 0.70。

检索位置的误差约为 0.13 × AGL（网格间距的一半），AGL 高于 `max_fallback_agl`（默认配置 1200 m）时不回退。

## 三、编译与配置

```bash
cd inference/single-so
bash rebuild_from_old_so.sh /path/to/old/libvNavigatorInterface.so
python3 tools/extract_runtime.py dist/libvNavigatorInterface.so /tmp/rt.tar.gz && tar -xzOf /tmp/rt.tar.gz --wildcards '*consistency.py' | grep -c check_fix   # > 0
```

`naviParams.txt` 的 `infrared` 段见 `naviParams.example.txt`，其中新增的两项：

```yaml
  tuning: {min_result_inliers: 15}
  consistency: {enabled: true, block_ratio: 0.75, altitude_m: 300, retrieval_fallback: true, max_fallback_agl: 1200}
```

其余项（`reference`、`camera`、`prior_tracking`、`retrieval_head`）沿用当前垂直配置；`prior_tracking` 里加上 `offset_model: true`。另外新增：

```yaml
  report_success: [fix, unconfirmed_fix, predicted]
```

| 输出来源 | 含义 | 模拟中误差 ≤150 m 的比例 | 默认是否算成功 |
|---|---|---|---|
| `fix` | 通过检验、被跟踪器接受的定位 | 约 0.7 | 是 |
| `unconfirmed_fix` | 捕获前、尚未确认的定位 | 较低 | 是 |
| `predicted` | 跟踪中定位失败，输出“先验 + 偏移量” | 约 0.5 | 是 |
| `retrieval` | 检索位置回退（捕获前） | 很低 | 否 |
| `search_centre` | 扫描中心，几乎总是错的 | 接近 0 | 否 |

模拟（同上）中，默认设置的成功率约 0.92、准确率 0.54；全部算成功时成功率 1.0、准确率 0.50；只报 `fix` 时成功率 0.31、准确率 0.71。成功率和准确率在总分里的权重不同，选择也不同：想提高准确率就删去 `predicted`，想提高成功率就加回 `retrieval`。

## 四、selfEval 打分标准

`vNaviResult.selfEval` 表示算法自己判断本帧位置是否满足精度要求。只有下面**全部**条件都满足才填 1.0，否则填 0.0（`infrared.self_eval`，`backends.py` + `self_eval.py`）：

| 条件 | 配置项（初值） | 依据 |
|---|---|---|
| 输出来源是已接受的定位 `fix` | `sources: [fix]` | 预测位置、检索位置、扫描中心、未确认的定位一律 0 |
| PnP 内点数足够 | `min_inliers: 30` | 匹配质量 |
| PnP 重投影误差小 | `max_reprojection_px: 4` | 几何一致 |
| 定位推算的视场地面点离检索块中心近 | `max_block_ratio: 0.5`（× 块边长） | 检索与匹配互相印证（比一致性检验的 0.75 更严） |
| PnP 高度与先验高度接近 | `max_dz_m: 150` | 高度不离谱 |
| 跟踪中，定位与预测位置接近 | `max_track_residual_m: 100` | 与前几帧连贯 |
| 检索得分明显高于不重叠的其他块 | `min_score_margin: 0.0` | 检索不含糊 |
| 多个候选给出一致位置（50 m 内） | `min_agreeing: 1` | 设为 2 更严 |

每帧日志 `[SELF_EVAL] frame=.. value=0/1 failed=..` 列出未满足的条件；`[NAV_TIMING]` 的 JSON 里有全部特征（`self_eval_features`）、输出来源和输出位置。

**标定**：初值没有用真实数据标定过。用加噪数据跑几条序列后：

```bash
python3 tools/calibrate_self_eval.py --log seq1.log --data data_noisy/day/IR/slant/sequence1 \
                                     --log seq2.log --data data_noisy/day/IR/slant/sequence2
```

脚本会给出：各输出来源的实际正确率（误差 ≤ 150 m）；在“selfEval=1 的帧中至少 95% 正确”（`--precision`）的前提下覆盖正确帧最多的阈值组合，并直接打印可粘贴的 `self_eval: {...}` 一行。日志就是推理运行时的控制台输出，或 `naviParams.txt` 同目录下的 `logs/timing.jsonl`。

## 五、日志与回退

| 日志 | 含义 |
|---|---|
| `[PNP_CHECK] rank=.. inliers=.. ok/outside_block/altitude dist=..m dz=..m` | 每个候选的检验结果 |
| `[FALLBACK] frame=.. retrieval position` | 本帧没有一致的 PnP 结果，输出检索位置 |
| `[PRIOR_OUT] source=... reported=0/1` | 本帧输出来源，以及是否作为定位成功返回 |

- 如果几乎每帧都是 `altitude` 且 `dz` 接近同一个值，说明 PnP 高度与先验高度的基准不同，把 `altitude_m` 调大（例如 600）。
- 如果正确结果被大量判为 `outside_block`，把 `block_ratio` 调到 1.0。
- 完全关闭：`consistency: {enabled: false}`，行为与原来相同。
