# 倾斜（DS/NS）训练与部署指南（2026-11-07）

本版本只服务倾斜红外数据，垂直数据继续用原来的权重、配置和 .so，两套互不影响。

验证范围：Linux CPU 上的单元测试和合成数据（训练端 81 项通过，含倾斜合成数据的 prepare → 提特征 → 训练 → 评估全流程测试；推理端 55 项通过，另 2 项需要编译 C++ 探针才能运行，原来就是如此）。另用物理渲染的倾斜图像验证了透视矫正：俯视图与旋转后的卫星图在光轴地面点处的相关系数为 0.94–0.98。**还没有在真实数据、训练服务器 GPU 或 Orin 上运行过**，请先按第二节跑小样本。

## 一、改了什么

### 1.1 倾斜数据的三个问题与对应改动

按文档中的倾斜参数，光轴俯角只有 15–17°（DS −15.3°，NS −17.3°），图像上沿只比地平线低 4–7°。

| 问题 | 改动 | 两端实现 |
|---|---|---|
| 按短边中心裁剪估算的块边长会到 8–13 km | 块大小改按“短边 × 0.5 的中心区域”的地面足迹估算，块约 3–3.6 km | 训练 `preprocess.query_crop_scale`；推理 `camera.query_crop_scale` |
| 相机看的是飞机前方约 2.4–5.4 km，而搜索窗口以飞机为中心，一半窗口在飞机身后 | 搜索地图中心移到光轴地面点：先在飞机先验处读 200 m 的 DSM 得到 AGL，再前移 AGL/tan(俯角)（约 3–3.5 km）。传给 SCC 的先验仍是飞机位置 | 训练 `scc_inference.frame_retrieval`；推理 `BaseBackend.prepare` |
| 倾斜红外图与正射卫星图透视不同 | 查询图按平地单应变换成“一个块大小、以光轴地面点为中心、航向朝上”的俯视图，与旋转后的卫星块同尺度同方向；查询看不到的像素在查询和每个候选块上同样置 0 | 共用 `oblique.py`（训练端 `scc_oblique.py` 为逐字节拷贝，测试比对）；推理 `feature_extract` 的 `tile_mask` |

开关是 `camera.oblique: true`（训练 `configs/slant.yaml`、推理 `naviParams.txt` 都要写）。俯视矫正假设地面平坦，忽略图像 roll（样例 |roll| < 1.5°）。

### 1.2 其余改动（前几天对话中确定的）

| 内容 | 文件 |
|---|---|
| 改 train 段参数（epochs、patience、lr 等）不再报 Config/cache mismatch | `train.py` |
| 余弦学习率下限 `train.min_lr`；每个 epoch 开始打印 `[train] epoch N start` | `train.py` |
| 修复双卡提特征误报 `Extraction worker failed`（PowerShell 退出码） | `scripts/extract_dual_gpu.ps1` |
| prepare 多进程（默认 CPU 核数 − 1，最多 8；`--workers N` 指定）、进度和剩余时间打印、DSM 读取缓存 | `prepare_dataset.py`、`geometry.py` |
| 先验误差为固定或缓慢变化偏移时的跟踪：中心 = 当前先验 + 最近一次定位的偏移量（`offset_model: true`） | 推理 `prior_tracker.py` |
| 定位失败时打印完整报错；打印检索前 5 名的经纬度 `[RETRIEVAL_TOP]` | 推理 `backends.py` |
| 检查工具 `slant_report.py`、`eval_one.py` | 训练端新增 |
| selfEval 打分标准（多项条件同时满足才为 1）及标定脚本，见 3.4 节 | 推理 `self_eval.py`、`tools/calibrate_self_eval.py` |
| 定位成功标志可配置 `report_success`：只有列出的输出来源返回 1，其余返回 0 | 推理 `backends.py`、`worker.py` |
| PnP 结果与检索块一致性检验：视场地面点须落在所匹配的检索块内（0.75 × 块边长），高度与先验相差 ≤ 300 m，否则丢弃，不输出、不用于跟踪 | 推理 `consistency.py`、`backends.py`（`infrared.consistency`） |

### 1.3 删除

LoRA、外观增强、DDP 训练（MLP 单卡训练只需几分钟）及其配置、脚本、测试和文档；垂直配置 `mlp.yaml`、`train_sequence.yaml`；过时的说明文档。

## 二、训练端

### 2.1 安装（离线服务器）

把 `vis-loc_slant_training_full_20261107.zip` 解压到**新目录**，例如 `D:\SCC_Retrieval\slant`。环境仍用原来的 `D:\SCC_Retrieval\env`；把旧工程的 `vendor\dinov2` 整个目录拷到新目录下。不要覆盖垂直版本的工程目录。

### 2.2 填写 `configs/slant.yaml`

| 字段 | 填什么 |
|---|---|
| `data.root`、`geo.satellite`、`geo.dsm` | 实际路径（与垂直版本相同） |
| `data.image_regex` | 默认已支持 `<序列目录>/<任意前缀><帧号>.jpg`（如 `sequence1/xxxx1000.jpg`）；逐图 TXT 支持 `key   value`（多个空格或 Tab）、`key=value`、`key: value`。如果垂直版本的配置或 `records.py` 在服务器上另外改过，把同样的设置抄过来 |
| `split.sequence_splits` | 倾斜数据中出现的全部序列名 → train / val（可不设 test） |
| `model.checkpoint`、`model.checkpoint_sha256` | 服务器上的 `dinov2_vitl14_pretrain.pth`，SHA256 为 `d5383ea8…cf428` |
| `inference.reference` | 与倾斜 .so 的 `naviParams.txt` 一致；**不要写 `resolution_m: 1`**（窗口约 10 km，沿用 DSM 网格） |
| `geo.normal_to_ellipsoid_m`、`geo.dsm_to_platform_offset_m` | 与垂直版本相同（已核实可填 0） |
| 四个 `*_confirmed` | 与垂直版本相同的核对后置 true；`pose.calibration_confirmed` 要在 2.3 第 3 步核对倾斜帧后再置 true |

其余参数已按倾斜数据设好：`query_crop_scale: 0.5`、`oblique: true`、`nadir_reference_alignment: false`、训练窗口 12 km / 验证 10 km、`altitude_error_m: 200`、`max_area_ratio: 8`、`epochs: 30`、`patience: 30`、`min_lr: 1e-5`。

### 2.3 小样本检查（必须先跑）

```powershell
cd D:\SCC_Retrieval\slant

& $py inspect_dataset.py --config configs/slant.yaml
powershell -ExecutionPolicy Bypass -File scripts\run_mlp.ps1 -EnvDir D:\SCC_Retrieval\env -Limit 30 -Steps prepare
& $py slant_report.py artifacts/slant/manifest.json
```

2. `slant_report.py` 每帧一行，例如：
   `DS/sequence1/1000  AGL 900 elev -15.4 block 3590 window 12000 footprint 2400-5300 m from aircraft, positives 3/30`
   - `elev` 应与记录中的 innsPitch 一致（−15° 左右）；
   - `block` 在 2–4 km 为正常。明显偏大就把两端的 `query_crop_scale` 一起改小（如 0.4），偏小就改大；
   - `positives` 应大于 0；
   - 末尾的 `FAIL` 行列出失败的帧和原因。
3. 打开 `artifacts/slant/diagnostics_prepare_*/contact_sheet.png`：左边查询图是**矫正后的俯视图**，应与右边的候选块方向一致、地物能对上；黑色区域是相机看不到的部分，候选块上同样是黑的。如果俯视图和候选块明显转了个角度或镜像，说明姿态约定不对，先停下来核对。
4. 确认后删掉 `artifacts\slant`，再跑全量。

## 三、推理端（倾斜 .so）

### 3.1 源码与编译

`vis-loc_slant_inference_full_20261107.zip` 是完整推理源码（`single-so/` 的 C++、Python 适配层、工具和测试，以及 `projects/SCC-Loc`、`projects/AnyVisLoc-Benchmark`），不含 ARM64 运行环境、权重和地图。在 ARM64 Ubuntu（与比赛机一致）上：

```bash
cd inference/single-so

bash rebuild_from_old_so.sh /path/to/old/libvNavigatorInterface.so
# 输出 dist/libvNavigatorInterface.so，最后打印 RUNTIME_OK 表示内嵌运行时自检通过
python3 tools/extract_runtime.py dist/libvNavigatorInterface.so /tmp/rt.tar.gz && tar -xzOf /tmp/rt.tar.gz --wildcards '*oblique.py' | grep -c rectify_query
# 输出大于 0 说明新代码已打进 .so
```

旧 .so 只用来取回内嵌运行时；新 .so 另存，垂直版本的 .so 保持不动。

### 3.2 naviParams.txt（`infrared` 段，见 `naviParams.example.txt`）

```yaml
infrared:
  project_root: ./projects/SCC-Loc
  pose_priori: yp
  retrieval_head: ./weights/scc_retrieval_head_slant.pth
  reference: {georeference: auto, image: ..., dsm: ..., height_datum: normal_m, window_m: 600, image_bands: [1, 1, 1]}
  prior_tracking: {enabled: true, acquisition: scan, prior_error_m: 5600, altitude_error_m: 200,
                   window_mode: meters, max_window_m: 10000, max_blocks: 100, hard_cap_m: 12000,
                   min_window_m: 600, min_fix_inliers: 40, offset_model: true}
  camera:
    reference_window_scale: 1.2
    nadir_reference_alignment: false
    oblique: true
    query_crop_scale: 0.5        # 必须与训练 configs/slant.yaml 相同
  tuning: {min_result_inliers: 15}
  consistency: {enabled: true, block_ratio: 0.75, altitude_m: 300, retrieval_fallback: false}
  report_success: [fix, unconfirmed_fix, predicted]
```

- `report_success`：哪些输出算定位成功（`stepVNavigator` 返回 1），其余帧返回 0。失败帧只影响成功率、不计入准确率，所以默认把扫描中心（几乎总是错的）报为失败。来源含义：`fix` 已接受的定位，`unconfirmed_fix` 捕获前未确认的定位，`predicted` 跟踪预测，`retrieval` 检索位置回退，`search_centre` 扫描中心。想提高准确率可以删去 `predicted`，想提高成功率可以加上 `search_centre`。

- `consistency`：PnP 结果要与它所匹配的检索块一致才采用。倾斜块约 3 km，用检索块中心换算出的飞机位置误差约 1 km，所以倾斜**不回退**到检索位置（`retrieval_fallback: false`），所有候选都不一致时按跟踪状态输出预测位置或搜索中心。
- 窗口已经以视场中心为中心，所以 `prior_error_m` 只填先验误差本身（最大 3 海里约 5600 m；确定最大 2 海里就填 3700，捕获更快）。
- `min_window_m: 600` 即可：跟踪时窗口会自动放大到至少 2 个块宽（约 7 km）。
- 把 `scc_retrieval_head_slant.pth` 及同名 `.json` 拷到 `weights/`。

### 3.3 上机检查

| 日志 | 看什么 |
|---|---|
| `[RETRIEVAL_HEAD] loaded ... (512-d)` | 检索头已加载 |
| `[OBLIQUE] frame=... block=...m visible=...` | 每帧都应出现；block 约 3 km，visible 约 0.5–0.7 |
| `[SEARCH_CENTER] ... map_center_from_prior_m=...` | 约等于 AGL/tan(俯角)（3 km 左右），说明窗口已前移到视场中心 |
| `[PRIOR_TRACK] mode=... window=...` | 窗口约 7–10 km；捕获后进入 `track` |
| `[PRIOR_OUT] source=... reported=0/1` | 从 `search_centre` 变为 `fix` / `predicted` 即已捕获；`reported=0` 的帧接口返回 0 |
| `[RETRIEVAL_TOP] rank=1 lon_lat=...` | 与真值对比可判断检索是否正确 |
| `[PNP_CHECK] rank=.. inliers=.. ok/outside_block/altitude dist=..m dz=..m` | 每个候选的一致性检验结果。如果几乎每帧都是 `altitude` 且 dz 接近同一个值，说明 PnP 高度与先验高度基准不同，把 `altitude_m` 调大 |
| `[NAV_TIMING] ... total_s` | 单帧 10 秒以内；超时可降 `max_window_m` |

定位失败时会打印完整报错堆栈。

### 3.4 selfEval 打分标准

`vNaviResult.selfEval` 表示算法自己判断本帧位置是否满足精度要求。只有下面**全部**条件都满足才填 1.0，否则填 0.0（`infrared.self_eval`，`backends.py` + `self_eval.py`）：

| 条件 | 配置项（初值） | 依据 |
|---|---|---|
| 输出来源是已接受的定位 `fix` | `sources: [fix]` | 预测位置、检索位置、扫描中心、未确认的定位一律 0 |
| PnP 内点数足够 | `min_inliers: 30` | 匹配质量 |
| PnP 重投影误差小 | `max_reprojection_px: 4` | 几何一致 |
| 定位推算的视场地面点离检索块中心近 | `max_block_ratio: 0.5`（× 块边长） | 检索与匹配互相印证（比一致性检验的 0.75 更严） |
| PnP 高度与先验高度接近 | `max_dz_m: 150` | 高度不离谱 |
| 跟踪中，定位与预测位置接近 | `max_track_residual_m: 100` | 与前几帧连贯 |
| 检索得分明显高于不重叠的其他块 | `min_score_margin: 0.0` | 检索不含糊 |
| 多个候选给出一致位置（50 m 内） | `min_agreeing: 1` | 设为 2 更严 |

每帧日志 `[SELF_EVAL] frame=.. value=0/1 failed=..` 列出未满足的条件；`[NAV_TIMING]` 的 JSON 里有全部特征（`self_eval_features`）、输出来源和输出位置。

**标定**：初值没有用真实数据标定过。用加噪数据跑几条序列后：

```bash
python3 tools/calibrate_self_eval.py --log seq1.log --data data_noisy/day/IR/slant/sequence1 \
                                     --log seq2.log --data data_noisy/day/IR/slant/sequence2
```

脚本会给出：各输出来源的实际正确率（误差 ≤ 150 m）；在“selfEval=1 的帧中至少 95% 正确”（`--precision`）的前提下覆盖正确帧最多的阈值组合，并直接打印可粘贴的 `self_eval: {...}` 一行。日志就是推理运行时的控制台输出，或 `naviParams.txt` 同目录下的 `logs/timing.jsonl`。

### 3.5 用加噪数据测试推理

现有数据的先验经纬度和高度与真值相同，用 `inference/tools/add_prior_noise.py`（只依赖 Python 标准库，Windows / Orin 都能运行）把整个数据目录复制一份，只改先验字段 `droneLongitude` / `droneLatitude` / `droneAltitude`，`*_gt` 保持不变（文件里没有 `*_gt` 时用原先验补上，真值不会丢）。原数据不会被修改。

```bash
# 缓慢漂移：每条序列误差从 3000 m 连续增大到 4000 m，方向最多转 30°，高度误差 ±200 m 内连续变化
python3 tools/add_prior_noise.py --src data --dst data_noisy_drift --mode drift --min-m 3000 --max-m 4000 --drift-increasing --alt-m 200
# 固定偏移：每条序列一个 2–3 海里的固定偏移（默认范围）
python3 tools/add_prior_noise.py --src data --dst data_noisy_const --mode const
# 逐帧随机：每帧独立的 2–3 海里误差
python3 tools/add_prior_noise.py --src data --dst data_noisy_random --mode random
```

- 支持 `key   value`（多个空格或 Tab）、`key=value`、`key: value` 和“表头 + 一行数据”的 CSV 四种 TXT 格式，保持原格式和原间隔只替换数值；兼容 `droneLongtitude` 拼写。
- `--jitter-m 20` 在固定 / 漂移误差上再叠加每帧独立的小噪声；`--seed` 固定随机数，结果可复现；`--link` 用硬链接代替复制图像（同一磁盘，省空间）。
- 每帧加的误差记录在 `<dst>/prior_noise_log.csv`（东、北、高度偏移和水平误差）。
- 训练不需要加噪数据：训练端的搜索中心本来就是“真值 + 随机偏移”。

### 3.6 回退

| 问题 | 回退 |
|---|---|
| 一致性检验误删正确结果 | `consistency: {enabled: false}` |
| 检索头效果差 | 删除 `retrieval_head` 一行（仍使用视场中心窗口和俯视矫正，只是用原 GeM 特征） |
| 俯视矫正或前移窗口有问题 | `oblique: false`（恢复以飞机为中心的窗口和中心裁剪；此时块会很大，需同时用原来的配置） |
| 跟踪不稳定 | `offset_model: false`，或 `prior_tracking: {enabled: false}` |
| 新 .so 有问题 | 换回旧 .so |

## 四、已知限制

- 俯视矫正按平地计算，起伏地形的远处会有几何误差；图像 roll 被忽略。
- 块大小、窗口和足迹距离都与 AGL 成正比。上面的数字按 AGL 约 900–1100 m、图像 640×512 估算，以 `slant_report.py` 实测为准。
- 检索之后的精匹配（MINIMA-RoMa）和 PnP 没有改动，倾斜视角下能否成功需在日志中确认。
- 推理端 DINO 为 fp16，训练端为 fp32 + autocast，数值差异很小。
