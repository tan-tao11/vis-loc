# 在训练前验证几何约定

可以验证，但要区分“公式自洽”“投影结果合理”和“真实标定准确”。单凭每帧经纬度、姿态与 FOV，不能唯一判断像素轴、安装矩阵和欧拉顺序是否正确。尤其 TXT 的 `droneLongitude_gt/Latitude_gt/Altitude_gt` 是平台位置真值，**不是图像中心的地面落点**。斜视图像的中心落点本来就可能与平台水平位置相距很远。

新增 `validate_geometry.py` 不需要 DINO、GPU、训练 manifest 或先把 `*_confirmed` 改成 true。它直接读取原配置、图像及 TXT，复用正式流程的几何和裁剪代码，输出报告与卫星叠加图。它不生成训练标签，不拟合或自动挑选安装矩阵，不修改配置，也不会自动宣告真实标定完成。

## 第一步：直接预检

服务器已有工程时，解压 `geometry_validation_update.zip` 到工程根目录，补充新增诊断文件。更新不覆盖 `configs/train.yaml`。全部功能也已纳入新的 `source.zip` 与 B 方式交付包，仍不包含 DINO 基座权重。

```powershell
cd D:\SCC_Retrieval_A\project
powershell -ExecutionPolicy Bypass -File scripts\validate_geometry.ps1 `
  -EnvDir D:\SCC_Retrieval_A\env -Config configs/train.yaml
```

同名逐图 TXT 使用 `data.per_image_txt: true`；路径和命名规则需对应真实目录。无需逐图抄写参数。默认跨 DS/DV/NS/NV 抽取最多 16 帧，每组尽量分散抽取；`-MaxFrames` 可调整。诊断可以在尚未定义训练地理划分时执行。

打开 `artifacts/geometry_validation/index.html`，同时检查：

| 输出 | 能说明什么 |
|---|---|
| `mapping_report.json` | 图像与 TXT 帧号、字段、序列、分组是否匹配；所有读取失败均保留 |
| `geometry_report.json` | 矩阵合法性、解析特例、光轴方向、相对地面高度、投影失败和地标误差 |
| `frame_*.png` | 查询实际中心裁剪、卫星预测足迹、图像右/下方向、平台位置、同名点误差线 |
| `footprints_wgs84.geojson` | 预测足迹的 WGS84 经纬度多边形，可导入 GIS；不把预测结果冒充独立真值 |

青色是预测足迹，黄色/紫色是图像向右/向下的地面方向，橙色是平台位置；有控制点时，绿色为人工或测绘确认的地面点，红色为按当前几何投影的点。真北方向由地理坐标计算，不能一概认为栅格图像上方就是真北。预览图会降采样显示，实际射线仍使用原 DSM 和几何坐标。

程序检查旋转正交性与 det=+1、EO 光轴与 INS +X 的接口约束、正航向向东/负俯仰向下的解析特例、下视射线与已知平面的交点。零姿态下非 EO 相机的实际安装方向仍需真实数据验证。射线朝天、穿地、DSM NoData/越界、缺少高程转换、足迹超出卫星范围等会明确报告，不替换成海拔零面。

退出码 0 只表示所选输入的自动检查未发现上述错误；没有地面控制点时，**不等于几何约定已被证实**。退出码 2 表示存在缺项、配对/投影错误或控制点超差，仍会留下可读报告。配置中的确认标志始终保持原值。

## 第二步：用独立地标确认轴向和误差

从标定用图像与卫星图中确认同一个路口、建筑角点等，记录它在原始查询图像的像素坐标和地面的 WGS84 经纬度。每幅尽量覆盖不同位置，可从 3–5 个分散地标开始，并覆盖不同航向、俯仰、相对地面高度，以及 EO/非 EO 两种链路。仅标图像中心不能发现绕光轴旋转 180° 等错误。

建立 UTF-8 CSV，例如以下只展示格式，数值必须替换为真实观测：

```csv
id,pixel_x,pixel_y,longitude,latitude,role
DS/sequence1/1000,120,80,87.1640,42.1060,calibration
DS/sequence2/1020,350,220,87.1670,42.1090,check
```

- `id` 必须精确对应 `mapping_report.json` 的帧 ID。
- `pixel_x` 向右、`pixel_y` 向下，采用原始图像坐标和当前 K 的坐标约定；不要填写经过中心裁剪或缩放到 336 后的坐标。
- `calibration` 是用于确定约定的标定点，`check` 是约定固定后保留的独立检查点。建议使用不同帧/航段；角色由用户提供，脚本不能证明其独立性。
- 地标不能来自同一套待验证几何投影生成的伪真值；合成点只能验证代码，不能验证真实标定。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\validate_geometry.ps1 `
  -EnvDir D:\SCC_Retrieval_A\env -Controls D:\calibration\controls.csv `
  -Output artifacts/geometry_controls
```

有控制点的帧会全部评估，即使超过 `-MaxFrames`。报告分 calibration/check 统计中位数、P95、最大值、RMSE，以及向东/向北的系统偏差；失败或未匹配点单独计数，不从验收分母中悄悄去掉。可追加 `-ToleranceM` 指定项目实际容许的米级误差，程序没有内置适用于所有数据的“合格米数”。容差应结合卫星地理精度、GSD、地标标注误差和任务指标设定。

默认使用 TXT 中的平台 `_gt` 位置投影，帮助把位置误差与姿态/安装误差区分开。再以 `-PositionSource prior` 使用原始先验位置检查整体部署误差。两次误差包含的因素不同，不应混在同一个统计中。

## 判断线索与确认边界

| 现象 | 优先排查的方向（不是唯一原因） |
|---|---|
| 中心接近，但四周地标翻转/旋转 | 像素右下轴、绕光轴安装角、旋转正负号 |
| 足迹在平台后方，或大量射线朝天 | NED/ENU 混用、pitch 符号、主动/被动旋转、矩阵乘法方向 |
| 仅 EO 或仅非 EO 出现系统错误 | 两条安装链混用、重复乘平台/转塔角 |
| 误差随斜视程度或高度增加 | 高程基准、DSM 单位、FOV/内参、姿态偏差 |
| 全部地标有相近平移偏差 | 相机位置、地图配准、高程/杆臂、时间同步 |
| 少数帧突跳 | TXT 帧配对、时间戳、NoData、角度异常 |

调整几何约定仅依据标定集与设备定义；约定固定后再检查独立点，不能逐帧依赖测试 GT 选择最优旋转或安装矩阵。平台 GT 只校正位置，并不提供姿态真值，也不证明图像与遥测时间同步。仅有总体召回变高不能作为几何正确的证据。

当前接口文档已明确 NED、角度单位为度、平台高度为正常高、EO 光轴平行 INS X；完整欧拉组合、像素轴安装、DSM 高程基准仍须通过设备定义和独立地标验证。验证结果足够后，再由使用者确认固定版本并设置相应标志；本工具不会代替这一判断。

距离采用 [pyproj 的 WGS84 椭球测地线计算](https://pyproj4.github.io/pyproj/stable/api/geod.html)，预览按 [Rasterio 窗口降采样](https://rasterio.readthedocs.io/en/stable/topics/resampling.html) 读取。当前只提供了样例参数和源码快照；合成验证不代表真实数据已经标定。

## 输出状态补充（2026-11-05）

独立几何诊断要求空输出目录，重复试验请为 `--output` 使用新名称。`frames.csv` 列出每帧状态、最大控制点误差和图像文件；`controls.csv` 给出每个控制点的总误差及东/北分量，单位均为米。HTML逐帧表明确标记 `control_out_of_tolerance`，即使足迹可计算也不会把控制点超差显示成通过。无控制点帧标为 `footprint_computable_unverified`；未给容差只显示测量结果，不判定合格。坏格式/缺失控制点CSV保留错误报告，命令退出2。所有状态均不等同于真实标定确认。
