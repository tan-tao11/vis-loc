# 按 sequence 划分训练、验证和测试

缺少 `regions.geojson` 时，可以显式启用 sequence 模式。它按完整航段分配集合，不需要地理区域文件；几何投影、候选生成、正负标签和正式数据确认检查仍照常执行。默认不配置 `split.mode` 时继续使用原来的 geographic 模式。

完整参考配置见 [train_sequence.yaml](../configs/train_sequence.yaml)。它启用逐图 TXT、固定候选尺寸，并使用独立输出 `artifacts/real_sequence`；路径、序列分配、高程基准及标定须按实际数据填写。空格 / Tab TXT 仍需应用已提供的解析器修改。配置文件本身不会自动确认真实几何。

在已有训练配置中修改 `split` 段，例如：

```yaml
split:
  mode: sequence
  regions_geojson: null
  buffer_m: 200
  sequence_exclusive: true
  sequence_splits:
    sequence1: train
    sequence2: train
    sequence3: val
    sequence4: test
```

替换为实际目录/记录中的 sequence 名称。所有已扫描到的序列必须有映射；遗漏会在投影前报错。此模式是显式指定航段分组，不会自动随机分配，也不按帧号范围切分。同名 sequence 在 DS/DV/NS/NV 中使用相同集合；同一实际航段或同一地点的关联数据应使用相同分组。不同航段恰好同名时也会绑定在一起，请提前统一命名。

应为训练和独立验证准备不同序列，保留独立测试序列用于最终评估。只有一个序列时不能获得独立的 sequence 级验证结果。序列中的帧数可以不同，所以各集合的图像比例不一定等于序列数量比例。少量 `--limit` 检查可能只包含一个集合，不适合作为完整训练 manifest。

仍从 `training/` 运行原来的数据准备命令：

```powershell
python prepare_dataset.py --config configs/train.yaml
```

`manifest.json` 和 `preparation_report.json` 保存 `split_mode`、`sequence_splits`、`split_counts`（后者在报告中）及 `split_warnings`。映射依据全部扫描记录建立，`--limit` 或某帧投影失败不会重新分配序列。

程序继续检查不同集合的查询/候选足迹重叠，在 sequence 模式下将地理重叠记录为警告，允许继续进行流程调试；这不是地理独立的评估。跨集合的完全重复图像仍会阻止制标签。训练所得指标不能直接作为跨地区泛化结果。geographic 模式继续把区域重叠作为错误处理。

此次更新修改了 `prepare_dataset.py`，已有 manifest / 特征缓存需重新生成，不能直接复用旧清单。不要为了开启 sequence 模式而更改真实数据的 `synthetic` 或未经核验的确认标记。
