# LoRA 轻量外观增强

本功能给 LoRA 增加训练图像增强，包含单卡和双卡 DDP 入口。MLP 仍使用原特征缓存；本次没有为 MLP 生成增强视图缓存。现有单卡、双卡代码和配置全部保留，已有基线及其断点可以继续使用原入口。

## 使用

进入工程目录后，选择一个入口：

```powershell
# 单卡，默认 cuda:0
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\train_lora_aug.ps1 -EnvDir D:\SCC_Retrieval_A\env
# 双卡，默认 cuda:0,cuda:1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\train_lora_aug_ddp.ps1 -EnvDir D:\SCC_Retrieval_A\env
```

默认读取已有 `artifacts/real/manifest.json`，分别写到 `artifacts/real/lora_aug`、`artifacts/real/lora_aug_ddp`，完成后自动调用原导出器，生成 `scc_retrieval_lora.pth`。自定义数据清单用 `-Manifest`，新输出目录用 `-Run`，设备用 `-Device`（单卡）或 `-Devices`（双卡）。数据、TXT 和几何配置无需再填一份。

配置分别是 `configs/lora_aug.yaml` 和 `configs/lora_aug_ddp.yaml`，可用 `-Config` 选择自己的增强配置。如果原 LoRA 配置已经调整了学习率、轮数或候选采样数，应把这些训练设置同步到增强配置后做对照。数据与部署预处理仍读取原 manifest。

## 默认增强内容

先按部署约定完成灰度映射、中心裁剪/姿态对齐和缩放，然后在单通道图像上施加以下外观扰动，再复制为三通道并使用原归一化。红外、卫星图像独立抽样，目前采用相同的轻量范围。

| 参数 | 默认值 | 含义 |
|---|---|---|
| `enabled` | `true` | 是否启用 |
| `preserve_probability` | `0.30` | 每张训练图像有 30% 概率保留原图，非每批固定比例 |
| `brightness_delta` | `0.05` | 在灰度 [0,1] 上加上 [-0.05,0.05] 的偏移 |
| `contrast_range` | `[0.90,1.10]` | 围绕当前图像均值调整对比度 |
| `gamma_range` | `[0.90,1.10]` | 小幅 Gamma 扰动 |
| `noise_probability` | `0.15` | 进入增强分支后，加高斯噪声的概率 |
| `noise_std_range` | `[0.002,0.01]` | [0,1] 灰度上的噪声标准差，约等于 0.51–2.55 个 uint8 灰度级 |
| `blur_probability` | `0.10` | 进入增强分支后，加高斯模糊的概率 |
| `blur_sigma_range` | `[0.30,0.80]` | 模糊标准差，单位像素，使用 5×5 核 |

亮度、对比度、Gamma 在增强分支中依次执行，模糊和噪声按各自概率执行，最后截断到合法 uint8 范围。保留原图概率为 30% 时，噪声/模糊的总体触发概率约为 10.5%/7%。这些是保守初值，并非在用户真实数据上选出的最优参数。

没有随机裁剪、旋转、翻转、缩放、遮挡、MixUp 或 CutMix；不改变图像尺寸、地理足迹、姿态、候选位置或正负标签，不对三个复制通道分别做颜色扰动。

## 训练、挖掘和验证的边界

只有训练损失的图像输入使用增强。困难负例挖掘、验证、测试、推理，以及原始基线均使用原图预处理。使用显式的训练视图接口，向该接口传入验证/测试样本会报错，不依赖 `model.train()` 状态来推断是否应增强。

每个进程使用独立增强随机数发生器，与候选采样和 dropout 的随机数分开。预览图也使用独立随机数，不改变训练序列。增强只在图像读入时执行一次；DINO 梯度检查点重算不会再次抽取增强。

增强运行保存自己的配置/代码指纹及增强随机数状态。恢复需要原配置、数据、设备和代码保持一致，命令示例：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\train_lora_aug.ps1 -EnvDir D:\SCC_Retrieval_A\env -Resume artifacts\real\lora_aug\last.pth
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\train_lora_aug_ddp.ps1 -EnvDir D:\SCC_Retrieval_A\env -Resume artifacts\real\lora_aug_ddp\last.pth
```

原基线的 checkpoint 继续使用原入口恢复，不能直接当成新增强训练的断点。新训练使用空目录，恢复使用原目录并保留 `best.pth`。

## 可视化与对照

- `augmentation_preview.png`：每个可训练分组的查询图、正候选图，展示原图及三个随机增强视图；保留原图的抽样会明确标注。它是示例预览，不是每一步实际输入的逐张记录。
- `augmentation_preview.json`：对应查询 ID、候选索引、增强参数和像素变化，记录合成数据标记。
- `history.json/csv/png`：损失、验证 R@1、梯度及增强累计计数；DDP 按 rank 分开记录计数。`seen` 只计入训练损失读图，不包含预览、挖掘或验证。`augmented` 表示进入增强分支，`pixels_changed` 记录实际改变的像素总数。
- `best_validation_review.json` 和报告目录：完整候选的验证结果、HTML、CSV、候选图。
- `best.pth` / `last.pth`：最佳验证权重和含增强 RNG 状态的完整 epoch 断点。导出权重继续兼容原 LoRA 推理适配器，推理不加增强。

做对照时保持训练轮数、学习率、有效全局批量、候选采样数及种子一致，将增强配置中的 `enabled` 改为 `false`，写入另一个 `-Run` 目录。也可以运行原无增强入口。主要比较独立地理验证集的 R@1/R@5 与 DS/DV/NS/NV 分组结果；不要因为增强训练损失较高就判定无效，测试集留给最终固定方案。

## 验证范围

81 项自动测试已通过。其中新增测试在 CPU 和双 CPU 进程上覆盖增强边界/参数检查、灰度通道一致、原图和几何标签不被修改、挖掘/验证不消费增强 RNG、预览不改变训练序列、关闭增强时与原单卡训练权重逐张量一致，以及单进程/DDP 连续训练与断点恢复逐张量一致。恢复会保存 CUDA RNG，但不承诺不同 CUDA 环境间逐位一致。

实际 DINO 小测使用本地 ViT-L/14 和合成 GIS 图像，验证训练梯度、冻结基座、原导出/重载及完整候选评估。准备机只有一张 RTX4060，双进程 CUDA 测试属于同卡诊断；不是双 A4000 的性能验收，也不是实际定位精度或增强收益的证明。

服务器可用以下命令在新的合成目录执行完整小测（不读取真实训练集）：

```powershell
. .\scripts\common.ps1
Set-EnvironmentPath D:\SCC_Retrieval_A\env
& D:\SCC_Retrieval_A\env\python.exe augmentation_smoke.py --output artifacts\augmentation_check --devices cuda:0,cuda:1
```

默认依次验证单卡和双卡。只测单卡可加 `--mode single`。同卡诊断必须显式传 `--diagnostic --devices cuda:0,cuda:0`，且不能据此报告双卡加速。
