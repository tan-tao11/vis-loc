| IR 图像 | `preprocess.query_image`：显式强度映射到 uint8、整数中心正方形裁剪、PIL BICUBIC 到 336×336 | 奇数宽高裁边、uint16 / float 范围、NoData、插值和裁剪顺序 |
| 卫星图块 | **已改为推理原代码**：`scc_geodata.GeoReference`（geodata.py 字节拷贝）读取并重采样到 DSM 工作网格 → `dumpRotateImage` → 与 `feature_extract` 相同的切片 → cv2 LINEAR 336 | 仅需核对训练配置 `inference` 段与部署 naviParams 相同 |
| 角度与像素坐标 | **已改为推理原代码**：`optical_pose` 的 yaw / 俯仰（含 `nadir_reference_alignment`、`optical_axis_in_inns`），块角点经 `invertAffineTransform(rotation)` 回到地图 | 推理端 isEO 取初始化值，训练按逐帧 isEO；camera 设置需与部署一致 |
| 归一化 | 灰度复制三通道；除以 255；mean `[0.485,0.456,0.406]`、std `[0.229,0.224,0.225]`；CHW | 两端输入 DINO 的同一张量，不能仅比较显示出来的图像 |
| 骨干 | `models.load_backbone`：非 register DINOv2 ViT-L/14，严格加载本地权重，冻结骨干 | 实际 SCC 的权重 SHA256、源码 commit / 字节指纹、模型结构；不能仅比较文件名 |

| MLP | IR / satellite 两个独立头；1024→512→512，中间 GELU / dropout，输出 L2 归一化 | domain 选择正确；只替换全局检索特征；不把 512 维送入 SGVA |
| LoRA | `lora.py`：默认最后 4 blocks 的 Q、V，rank=8、alpha=16、dropout=0.05；共享检索适配器，GeM 输出 1024 维，无额外 MLP | 单独构建检索 DINO；不将 LoRA 合并进 MINIMA/RoMa 的共享匹配骨干；推理 eval 关闭 dropout |
| 候选协议 | **已改为推理原代码**：先验 window_m 搜索窗、`estimate_reference_side`×scale 单一块尺寸、retrieval_overlap_percent 步长、`compute_block_mid_wo_black` 黑边过滤，顺序与推理相同 | 验证/测试与推理一致；训练集可用更大的 train_window_m 并子采样负例 |
| 检索打分 | `evaluate.py`：归一化描述子点积，高分优先；稳定排序在同分时保留候选顺序 | 原候选 ID 对应关系、同分处理、Top-K；SGVA 修改后的图块不能代替排序前原图块 |
| 数据增强 | 仅 LoRA 增强训练入口启用灰度外观扰动；不改变几何 | 挖掘、验证、测试、推理使用无增强图像；MLP 缓存基线不隐式增加增强 |
| 缓存 | manifest / 特征元数据绑定源代码、骨干和预处理身份 | 更换 checkpoint、源码或预处理后核验 / 重建缓存；不能继续使用旧全局描述子 |

## 推理导出接口

| 方案 | 导出端 | 推理入口 | 输出 |
|---|---|---|---|
| MLP | `export.py` | `integration.retrieval_adapter.RetrievalAdapter` | 512 维归一化描述子 |
| LoRA | `export_lora.py` | `integration.lora_adapter.LoRAInferenceAdapter` | 1024 维归一化描述子 |

两种导出格式不能互换。推理使用导出权重及同名 `.json` 元数据，不把训练 checkpoint 直接当作推理导出物。导出文件记录结构、backbone 身份、预处理 / 姿态指纹、`synthetic_only` 及验证集选模信息。大文件通过既有部署渠道交换，Git 中只记录身份和接口。

MLP 的 `apply_dense_result` 和 LoRA 的 `replace_global` 保留原 dense / CLS 对象，供 SGVA 和匹配继续使用。LoRA 还必须保留原始 DINO 的匹配路径，额外的检索骨干需要独立核算显存。

默认拒绝合成诊断权重用于生产。指纹不符、权重缺失或结构不符时应保留报错；显式 fallback 会改变检索行为，不能被当作完成接入。MLP 加载器只检查显式传入的权重哈希与预处理 / 姿态指纹，完整源码及特征路径仍需人工和数值回归；LoRA 会比较完整骨干身份字典。

## 两端验收步骤

1. **固定身份**：记录训练仓库 commit、推理仓库 commit（合并后可为同一 commit）、DINO 源码和权重 SHA256、导出物 SHA256、配置指纹、PyTorch / CUDA / 图像库版本、设备及精度模式。
2. **固定同一批输入**：在两端用相同影像、对应 TXT、卫星 / DSM、原始先验和候选 ID。真实文件通过授权的大文件渠道交换，不入 Git。
3. **逐层比较**：原始字段与单位 → 位姿矩阵 / 地面足迹 → 候选 ID / box / 逆矩阵 → uint8 图块 → 归一化张量 → 原始 GeM → MLP 或 LoRA 描述子 → 分数 / Top-K → 匹配点坐标回映射。保存两端输出及差异报告，先定位最早出现差异的一层。
4. **先控制数值变量**：先用一致设备 / FP32 路径定位逻辑差异，再比较实际 AMP / 设备组合。报告最大绝对误差、描述子余弦差、Top-K / 同分差异和像素 / 米级几何偏差。容差须根据实际设备和精度模式确定；当前未设定未经实测的通用验收阈值。
5. **保护匹配路径**：确认检索适配器只改变 global 描述子，原 dense / CLS 的形状、内容和用途不变；检查 SGVA 与匹配输出。
6. **核验后更新状态**：在本文件记录证据和剩余差异，再更新真实运行配置中的确认项。已有 81 项测试或合成流程通过，并不能自动证明上述真实两端验收通过。

## Prepare 性能优化

数据准备通过 `local_rotated_crop(..., mask_only=True)` 仅计算有效掩膜和角点，跳过不参与标签计算的强度转换与灰度图双三次插值。强度范围、NoData、有限值、边界腐蚀和掩膜变换仍按原规则检查。完全有效的矩形掩膜直接构造边界多边形，并保持 GDAL 的浮点运算顺序；含无效像素的窗口仍使用原多边形提取。候选数量、顺序、尺度及标签规则不变；特征提取和推理默认仍生成完整图块。

本机合成栅格的 300 个候选局部基准（裁剪＋有效区域多边形）为修改前 2.35 秒、修改后 0.20 秒；这是内存栅格测试，不代表真实服务器整帧耗时。源码指纹已改变，应以新 output 重新 prepare 并重建关联特征缓存，保留旧运行目录。

## 2026-11-05 训练候选改为推理原代码生成（MLP 精简流程）

- **同源代码**：`scc_geodata.py` 是 `inference/single-so/python/geodata.py` 的字节拷贝；`scc_inference.py` 逐字拷贝 `camera_matrix`、`optical_pose`（backends.py）和 `dumpRotateImage`、`estimate_reference_side`、`compute_block_mid_wo_black`、`crop_center`（SCC-Loc/utils.py）。`tests/test_inference_alignment.py` 在仓库内逐一比对源码；推理端修改后须重新拷贝。训练服务器上没有 `inference/` 目录时这些比对会跳过，运行行为不变。
- **每帧流程**：先验 lon/lat/altitude（不用 *_gt）→ `GeoReference.for_frame` 读取 window_m 地图（DSM 工作网格、image_bands、image_value_range 与部署相同）→ AGL=高度−DSM(先验) → `optical_pose` 得 yaw/俯仰 → `dumpRotateImage` → `estimate_reference_side`×reference_window_scale → 50% 步长网格 + 黑边过滤 → 每块按 feature_extract 的整数切片裁剪并 cv2 缩放到 336。manifest 只存块中心与该帧遥测，提特征、LoRA 和候选图都用 `TileSource` 按同一流程重建，并核对块尺寸和块数。
- **查询图**：`preprocess.query_image` 与 `crop_center(min边)`+PIL 缩放逐像素一致（8 位 IR，含奇数宽高，已测）。
- **标签**：块的地图多边形与标定后的真值足迹（geometry.py）计算覆盖率；真值只用于打标签，从不进入候选生成。
- **训练集专用**：`train_window_m` 让训练集用更大的搜索窗（同一取图流程，只是窗口更大），`train_negatives` 子采样负例；验证/测试使用推理窗口和完整块集合，`eval_query_stride` 抽帧。
- **卫星强度检查**：inspect / prepare / 候选图按 GeoReference 的 uint8 转换统计纯白/纯黑比例，>90% 报错并给出建议的 `image_value_range`。
- **已删除**：旧的固定多尺寸/搜索半径候选协议、低分辨率有效性网格、`preprocess.local_rotated_crop` 等。配置 `candidates` 只剩 train_window_m / train_negatives / eval_query_stride。
- **仍需注意**：推理 C++ 把初始化时的 isEO 传给逐帧 metadata，训练按逐帧 isEO；非 EO 组在 yp 下需要 `optical_axis_in_inns` 或 `nadir_reference_alignment`，否则推理和训练都会拒绝该帧（可用 `camera_by_group` 按组照抄部署设置）。DINO 前向在训练中 GeM 固定 FP32，推理在 autocast 下计算，数值差异需在目标机核对。

## 2026-11-05 大先验误差：定位跟踪 + 扫描捕获（推理），真值邻域搜索窗（训练）

比赛先验经纬度误差可达 2–3 海里（3.7–5.6 km）、高度 ±200 m，误差可能逐帧独立，也可能连续漂移；真实轨迹连续（可转弯），单帧预算 10 秒，计分为误差 >150 m 记 0 分、所有帧取平均。

- **推理**（`inference/single-so/python/prior_tracker.py`，`BaseBackend.prepare` / `localize_tracked`）：
  - 跟踪（主方案）：捕获到的第一个定位只是"待确认"；下一帧在它附近的小窗口里再定位一次，两次一致才进入跟踪。之后中心 = 上次定位 + 速度（最近两次定位之差），半径 150 m + 20 m/帧；只接受该半径内的定位；超过 15 帧没有被接受的定位就回到捕获阶段。不依赖先验误差的形式。
  - 捕获：默认 `scan`，以平滑先验（最近 30 帧稳健直线拟合）为基准，逐帧扫描 `max_window_m` 大小的窗口，覆盖半径 `prior_error_m`。另有 `smooth`（只看平滑中心）和 `hybrid`（二者交替）。
  - 输出：被接受的定位直接输出；跟踪或待确认阶段定位失败、不可信时输出预测位置（置信度 0）；捕获阶段输出原始结果。
  - 模拟（每帧 100 m、S 形转弯，检索成功率 70%、10% 的错误匹配内点也高）：
    - 2 km 窗口：scan 对逐帧随机和连续漂移误差的得分都是 0.55；smooth 分别为 0.80 和 0.00；hybrid 分别为 0.77 和 0.39。
    - 3 km 窗口：scan 得分 0.70 / 0.74，首次确认锁定的中位数在第 34 / 22 帧。
    - 窗口大小是最大的杠杆，`max_window_m` 应在 10 秒预算内尽量取大。
  - 转弯：速度取自定位结果，每帧 200 m、急转弯时，锁定后窗口命中率约 0.98（用平滑斜率时只有 0.47）。
- **训练**：推理端的搜索中心取决于未知的先验误差形式，而检索模型只在真实位置落进窗口后才起作用。因此所有划分的中心 = 真值 + ≤`center_offset_m`(300 m) 随机偏移，高度 = 真值 ±`altitude_error_m`(100 m)，窗口分别为 `train_window_m`(1200 m) 和 `eval_window_m`(2000 m，= 捕获扫描窗口)。真值只用来放置窗口；候选块仍是推理原样生成的网格，不插入真值块。验证指标衡量的是"真实位置在窗口内时的检索排名"，与先验误差形式无关。训练端不再使用跟踪器。
- **正样本阈值**：推理网格（块 = 1.2×足迹，步长 50%）在最坏错位时，最佳块只覆盖约 64% 的足迹，因此 `labels.positive_coverage` 由 0.8 改为 0.6，保证真实位置在窗口内的帧都有正样本。
- **块尺寸余量**：高度低估约 17% 以上时块会明显小于足迹。若实际 AGL 较低，可提高 `reference_window_scale`（两端同时改）。
