# 训练与推理对齐清单

状态：训练端源码已整理；当前实际推理端源码待同步。以下表格记录**当前训练实现**，不是已经完成两端对齐的声明。本文训练文件路径以 `training/` 为基准，历史附件位于 `training/reference/scc_snapshot/`；现网实现应放在仓库根目录下并列的 `inference/`。

## 必须逐项对齐的约定

| 项目 | 当前训练实现 / 证据入口 | 推理端需要核验 |
|---|---|---|
| 输入字段 | `records.py`、`configs/train.yaml`：CSV / key=value 块 / 逐图 TXT，严格字段和组别映射 | 实际 TXT 字段、单位、时间和图像对应关系；特别是 EO / 非 EO 分支 |
| 位姿与高度 | `geometry.py`：列向量、主动旋转、NED、配置化 ZYX 及安装矩阵；正常高 / 椭球高与 DSM 基准显式处理 | `backends.py`、真实标定和高程基准；当前标定及垂直基准仍未确认 |
| IR 图像 | `preprocess.query_image`：显式强度映射到 uint8、整数中心正方形裁剪、PIL BICUBIC 到 336×336 | 奇数宽高裁边、uint16 / float 范围、NoData、插值和裁剪顺序 |
| 卫星图块 | `local_rotated_crop` + `candidate_image`：等价于 PIL expand 旋转后裁块，再 OpenCV LINEAR 到 336×336 | 同一原始候选的 box、角度、逆变换、有效区域及逐像素结果 |
| 角度与像素坐标 | `geometry.reference_angle` 使用图像右轴投影；`rotation_affine` 返回 PIL 角点坐标逆变换 | 推理 yaw 的来源；像素中心索引回映射要先 +0.5，变换后再 −0.5 |
| 归一化 | 灰度复制三通道；除以 255；mean `[0.485,0.456,0.406]`、std `[0.229,0.224,0.225]`；CHW | 两端输入 DINO 的同一张量，不能仅比较显示出来的图像 |
| 骨干 | `models.load_backbone`：非 register DINOv2 ViT-L/14，严格加载本地权重，冻结骨干 | 实际 SCC 的权重 SHA256、源码 commit / 字节指纹、模型结构；不能仅比较文件名 |
| GeM | `models.gem`：归一化 patch tokens，FP32，clamp≥1e-6，p=4，token 维均值，L2 归一化；1024 维 | 不使用 CLS 代替 GeM；核验 autocast、pooling、clamp 和归一化顺序 |
| MLP | IR / satellite 两个独立头；1024→512→512，中间 GELU / dropout，输出 L2 归一化 | domain 选择正确；只替换全局检索特征；不把 512 维送入 SGVA |
| LoRA | `lora.py`：默认最后 4 blocks 的 Q、V，rank=8、alpha=16、dropout=0.05；共享检索适配器，GeM 输出 1024 维，无额外 MLP | 单独构建检索 DINO；不将 LoRA 合并进 MINIMA/RoMa 的共享匹配骨干；推理 eval 关闭 dropout |
| 候选协议 | `prepare_dataset.py`：显式先验窗、多尺度 / 高度偏差、有效区域筛选；完整候选保留 ID | 实际 `backends.py` 的尺度公式、先验位置 / 高度、窗口、枚举顺序和筛选；当前不能证明等价 |
| 检索打分 | `evaluate.py`：归一化描述子点积，高分优先；稳定排序在同分时保留候选顺序 | 原候选 ID 对应关系、同分处理、Top-K；SGVA 修改后的图块不能代替排序前原图块 |
| 数据增强 | 仅 LoRA 增强训练入口启用灰度外观扰动；不改变几何 | 挖掘、验证、测试、推理使用无增强图像；MLP 缓存基线不隐式增加增强 |
| 缓存 | manifest / 特征元数据绑定源代码、骨干和预处理身份 | 更换 checkpoint、源码或预处理后核验 / 重建缓存；不能继续使用旧全局描述子 |

相关实现说明见 [接入说明](接入说明.md)、[方法与边界](方法与边界.md)、[几何验证](几何验证.md)、[LoRA 备选方案](LoRA备选方案.md) 和 [数据增强](数据增强.md)。

数据划分支持默认 geographic 模式和显式 sequence 模式，后者不需要 `regions.geojson`，按同名航段跨 DS/DV/NS/NV 固定分组。sequence 模式会记录地理重叠警告，不代表跨地区独立验收；两端比较同一训练结果时需记录 manifest 的划分模式及序列映射。具体配置见 [序列划分](序列划分.md)。

## 推理导出接口

| 方案 | 导出端 | 推理入口 | 输出 |
|---|---|---|---|
| MLP | `export.py` | `integration.retrieval_adapter.RetrievalAdapter` | 512 维归一化描述子 |
| LoRA | `export_lora.py` | `integration.lora_adapter.LoRAInferenceAdapter` | 1024 维归一化描述子 |

两种导出格式不能互换。推理使用导出权重及同名 `.json` 元数据，不把训练 checkpoint 直接当作推理导出物。导出文件记录结构、backbone 身份、预处理 / 姿态指纹、`synthetic_only` 及验证集选模信息。大文件通过既有部署渠道交换，Git 中只记录身份和接口。

MLP 的 `apply_dense_result` 和 LoRA 的 `replace_global` 保留原 dense / CLS 对象，供 SGVA 和匹配继续使用。LoRA 还必须保留原始 DINO 的匹配路径，额外的检索骨干需要独立核算显存。

默认拒绝合成诊断权重用于生产。指纹不符、权重缺失或结构不符时应保留报错；显式 fallback 会改变检索行为，不能被当作完成接入。MLP 加载器只检查显式传入的权重哈希与预处理 / 姿态指纹，完整源码及特征路径仍需人工和数值回归；LoRA 会比较完整骨干身份字典。

## 两端验收步骤

1. **固定身份**：记录训练仓库 commit、推理仓库 commit（合并后可为同一 commit）、DINO 源码和权重 SHA256、导出物 SHA256、配置指纹、PyTorch / CUDA / 图像库版本、设备及精度模式。
2. **固定同一批输入**：在两端用相同影像、对应 TXT、卫星 / DSM、原始先验和候选 ID。真实文件通过授权的大文件渠道交换，不入 Git。
3. **逐层比较**：原始字段与单位 → 位姿矩阵 / 地面足迹 → 候选 ID / box / 逆矩阵 → uint8 图块 → 归一化张量 → 原始 GeM → MLP 或 LoRA 描述子 → 分数 / Top-K → 匹配点坐标回映射。保存两端输出及差异报告，先定位最早出现差异的一层。
4. **先控制数值变量**：先用一致设备 / FP32 路径定位逻辑差异，再比较实际 AMP / 设备组合。报告最大绝对误差、描述子余弦差、Top-K / 同分差异和像素 / 米级几何偏差。容差须根据实际设备和精度模式确定；当前未设定未经实测的通用验收阈值。
5. **保护匹配路径**：确认检索适配器只改变 global 描述子，原 dense / CLS 的形状、内容和用途不变；检查 SGVA 与匹配输出。
6. **核验后更新状态**：在本文件记录证据和剩余差异，再更新真实运行配置中的确认项。已有 81 项测试或合成流程通过，并不能自动证明上述真实两端验收通过。
